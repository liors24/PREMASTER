# מעקב הזמנות רכש

מערכת לניהול ומעקב הזמנות רכש: טבלה מרכזית שעובדת כמו אקסל, לשונית לכל פרויקט, דשבורד ומעקב השלמת מכלולים לפי BOM.
אתר סטטי שרץ ב-GitHub Pages. כל הנתונים נשמרים בקובץ JSON במאגר גיטהאב, והשינויים מסתנכרנים אוטומטית בין כל המשתמשים.

## שימוש מיידי

פותחים את האתר, נרשמים ומייבאים את קובץ האקסל, בכפתור או בגרירת הקובץ לחלון. אין צורך בחיבור לגיטהאב: הנתונים נשמרים בדפדפן של המכשיר.
כדי לסנכרן בין מכשירים ועורכים, מתחברים לגיטהאב בתפריט המשתמש, "חיבור לגיטהאב". הנתונים שכבר הוזנו עוברים למאגר אוטומטית.

## חיבור לגיטהאב לסנכרון (אופציונלי)

כדאי להשתמש בשני מאגרים:

| מאגר | מה יש בו | פרטי או ציבורי |
|---|---|---|
| `procurement-app` (לדוגמה) | הקבצים של התיקייה הזו (קוד האתר בלבד) | ציבורי (GitHub Pages חינמי עובד רק ממאגר ציבורי) |
| `procurement-data` (לדוגמה) | קובץ הנתונים, נוצר אוטומטית | **פרטי** |

1. יוצרים מאגר `procurement-app` ומעלים אליו את כל הקבצים (index.html, תיקיית css, תיקיית js).
2. ב-Settings ← Pages בוחרים Branch: `main` ותיקייה `/ (root)`. אחרי דקה האתר זמין בכתובת `https://<user>.github.io/procurement-app/`.
3. יוצרים מאגר **פרטי** וריק `procurement-data`.
4. יוצרים טוקן: Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens.
   - Repository access: רק `procurement-data`
   - Permissions ← Contents: **Read and write**
5. פותחים את האתר, ממלאים שם משתמש, שם מאגר וטוקן, ולוחצים "בדיקה וחיבור".
6. כדי לחבר מחשב או טלפון נוסף: תפריט המשתמש ← "קישור חיבור למכשיר נוסף". הקישור כולל את הטוקן, ולכן כדאי לשלוח אותו רק לעורכים מורשים.

## מה יש במערכת

- **כניסה מאובטחת**: הרשמה ראשונית עם שם פרטי, שם משפחה וסיסמה. הסיסמה נשמרת מוצפנת בגיבוב SHA-256 עם salt.
- **טבלה מרכזית**: ייבוא מאקסל (xlsx, xls, csv). הכותרות נקלטות כמו שהן, וייבוא חוזר מעדכן שורות לפי עמודת מפתח.
- **עבודה כמו באקסל**:
  - שינוי רוחב עמודה ע"י גרירת קצה הכותרת. לחיצה כפולה על הקצה מתאימה את הרוחב לתוכן.
  - שינוי גובה שורה ע"י גרירת הקצה התחתון של מספר השורה.
  - בחירת כמה שורות, עמודות או טווחים: Shift, Ctrl וגרירה.
  - Ctrl+Enter מחיל את הערך שהוקלד על כל התאים המסומנים.
  - Ctrl+D ממלא למטה, וגרירת ידית המילוי מעתיקה ערכים וממשיכה סדרות מספרים.
  - העתקה והדבקה מאקסל וחזרה (Ctrl+C / Ctrl+V).
  - ביטול וחזרה (Ctrl+Z / Ctrl+Y).
  - סינון ערכים, מיון, חיפוש, הוספה ומחיקה של שורות ועמודות, הסתרה וגרירה לשינוי סדר.
  - בשורת המצב: ספירה, סכום וממוצע של התאים המסומנים.
- **לשוניות פרויקט אוטומטיות**: כל ערך בעמודת הפרויקט פותח לשונית. אם שם פרויקט מוחלף בטבלה, הלשונית משנה את שמה ושומרת את ה-BOM. שינוי שם בלשונית (לחיצה ימנית) מעדכן את כל ההזמנות שלה. פרויקט שאין לו יותר הזמנות יורד מהלשוניות. הסיסמה של כל לשונית היא שם הפרויקט.
- **דשבורד לכל פרויקט**: כמה הזמנות קיימות, נשארו פתוחות, סופקו, סגורות, בעיכוב או דורשות טיפול, וחדשות. בנוסף: רשימת הזמנות באיחור, אספקות קרובות ופילוח לפי ספק. לחיצה על מדד פותחת את הטבלה מסוננת לפיו.
- **BOM ומכלולים**: ייבוא BOM לכל פרויקט. כל מק"ט מותאם להזמנות של הפרויקט, ולכל מכלול מוצג אחוז השלמה במד מקטעים, כשכל מקטע הוא מק"ט אחד.
- **סקירת פרויקטים**: השוואה בין כל הפרויקטים בלשונית המרכזית.
- **גיבוי**: ייצוא לאקסל מכל טבלה, וגיבוי או שחזור של כל הנתונים כקובץ JSON.

## נפח נתונים

המערכת נבדקה עם 10,000 שורות ו-30 עמודות:

| פעולה | זמן |
|---|---|
| קריאת הקובץ | כ-0.8 שניות |
| ייבוא | כ-0.7 שניות |
| טעינה מחדש | פחות משנייה |
| עריכה של עמודה שלמה וביטול שלה | פחות מחצי שנייה |

השמירה המקומית משתמשת ב-IndexedDB של הדפדפן ולא ב-localStorage, שמוגבל ל-5MB. הנתונים נשמרים בגיטהאב כקובץ דחוס (gzip): 10,000 שורות תופסות כ-1MB במקום כ-10MB.

## איך הסנכרון עובד

כל שינוי נשמר מקומית מיד ונשלח לגיטהאב אחרי שנייה. כל 12 שניות, וגם כשחוזרים ללשונית הדפדפן, המערכת בודקת אם יש עדכונים ממשתמשים אחרים.
המיזוג נעשה ברמת השורה: אם שני משתמשים עורכים שורות שונות באותו זמן, נשמרים השינויים של שניהם. אם שניהם ערכו את אותה שורה, נשמרת העריכה האחרונה.
אם אין חיבור לאינטרנט, השינויים נשמרים במכשיר ונשלחים כשהחיבור חוזר.

js/app.js        המסכים והתצוגות
