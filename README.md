# מעקב הזמנות רכש

מערכת לניהול ומעקב הזמנות רכש: טבלה מרכזית שעובדת כמו אקסל, לשונית לכל פרויקט, דשבורד ומעקב השלמת מכלולים לפי BOM.
אתר סטטי שרץ ב-GitHub Pages. כל הנתונים נשמרים בקובץ JSON במאגר גיטהאב, והשינויים מסתנכרנים אוטומטית בין כל המשתמשים.

## שימוש מיידי

פותחים את האתר, נרשמים ומייבאים את קובץ האקסל, בכפתור או בגרירת הקובץ לחלון. אין צורך בחיבור לגיטהאב: הנתונים נשמרים בדפדפן של המכשיר.
כדי לסנכרן בין מכשירים ועורכים, מתחברים לגיטהאב בתפריט המשתמש, "חיבור לגיטהאב". הנתונים שכבר הוזנו עוברים למאגר אוטומטית.

## כניסה מכל מכשיר

אחרי החיבור לגיטהאב, המשתמשים והנתונים משותפים לכל המכשירים:
- **במכשיר חדש** פותחים את האתר ונכנסים עם שם, שם משפחה וסיסמה. המכשיר מתחבר לנתונים המשותפים לבד.
- **עורך חדש** נרשם ממכשיר חדש עם קוד הצוות `KADAM`. אחרי ההרשמה הוא נכנס עם השם והסיסמה מכל מכשיר.
- **איך זה עובד:** טוקן הגישה נשמר בקובץ `access.json` במאגר האתר כשהוא מוצפן בנפרד בסיסמה של כל משתמש (PBKDF2 עם 210,000 סבבים ו-AES-256-GCM). הוא לא נשמר בקובץ כטקסט גלוי. לכן יש חובה לסיסמה של לפחות 8 תווים.
- **הטוקן צריך הרשאה לשני מאגרים:** מאגר הנתונים ומאגר האתר, שניהם עם Contents: Read and write.

## חיבור לגיטהאב לסנכרון

כדאי להשתמש בשני מאגרים:

| מאגר | מה יש בו | פרטי או ציבורי |
|---|---|---|
| `procurement-app` (לדוגמה) | הקבצים של התיקייה הזו (קוד האתר בלבד) | ציבורי (GitHub Pages חינמי עובד רק ממאגר ציבורי) |
| `procurement-data` (לדוגמה) | קובץ הנתונים, נוצר אוטומטית | **פרטי** |

1. יוצרים מאגר `procurement-app` ומעלים אליו את כל הקבצים (index.html, תיקיית css, תיקיית js).
2. ב-Settings ← Pages בוחרים Branch: `main` ותיקייה `/ (root)`. אחרי דקה האתר זמין בכתובת `https://<user>.github.io/procurement-app/`.
3. יוצרים מאגר **פרטי** וריק `procurement-data`.
4. יוצרים טוקן: Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens.
   - Repository access: רק `procurement-data`
   - Permissions ← Contents: **Read and write**
5. פותחים את האתר, ממלאים שם משתמש, שם מאגר וטוקן, ולוחצים "בדיקה וחיבור".
6. כדי לחבר מחשב או טלפון נוסף: תפריט המשתמש ← "קישור חיבור למכשיר נוסף". הקישור כולל את הטוקן, ולכן כדאי לשלוח אותו רק לעורכים מורשים.

## מה יש במערכת

### מבנה הלשוניות

| לשונית | מה יש בה |
|---|---|
| **דשבורד משולב** | כל הפרויקטים יחד. לכל פרויקט כרטיס עם הזמנות קיימות, פתוחות, סופקו, סגורות, בעיכוב וחדשות, אחוז השלמת ה-BOM, התקדמות האספקות, ושלושת המכלולים שהכי רחוקים מהשלמה. |
| **הזמנות** | טבלת ההזמנות המלאה (ייבוא נפרד) ודשבורד הזמנות: מדדים, מצב ההזמנות, השוואה בין פרויקטים, הזמנות באיחור, אספקות קרובות ופילוח לפי ספק. |
| **BOM** | טבלת ה-BOM המלאה (ייבוא נפרד) ודשבורד BOM: השלמה לפי פרויקט ולפי מכלול, מק"טים שסופקו, שהוזמנו, שבעיכוב ושלא הוזמנו, ורשימת מק"טים שעוד לא הוזמנו. |
| **לשונית לכל פרויקט** | דשבורד משולב של הפרויקט, ההזמנות שלו וה-BOM שלו. הלשונית נעולה בסיסמה: `KADAM`. |

### טבלת ה-BOM
- מייבאים אותה בנפרד, בלשונית BOM או בגרירת הקובץ לחלון.
- בייבוא מתאימים את עמודות הקובץ לשדות פרויקט, מכלול, מק"ט, תיאור וכמות. שאר עמודות הקובץ נכנסות כעמודות נוספות בטבלה.
- אם בקובץ אין עמודת פרויקט, בוחרים בייבוא לאיזה פרויקט הוא שייך.
- אופני ייבוא:
  - החלפת ה-BOM של הפרויקטים שבקובץ
  - הוספה ל-BOM הקיים
  - החלפת כל ה-BOM
- כל מק"ט ב-BOM מותאם להזמנות של אותו פרויקט עם אותו מק"ט. כך מחושב לכל מק"ט מצב אספקה: סופק, הוזמן, בעיכוב או לא הוזמן.
- אחוז ההשלמה של מכלול הוא ממוצע ההשלמה של המק"טים שבו.

### עבודה כמו באקסל (בשתי הטבלאות)
- שינוי רוחב עמודה ע"י גרירת קצה הכותרת. לחיצה כפולה על הקצה מתאימה את הרוחב לתוכן.
- שינוי גובה שורה ע"י גרירת הקצה התחתון של מספר השורה.
- בחירת כמה שורות, עמודות או טווחים: Shift, Ctrl וגרירה.
- Ctrl+Enter מחיל את הערך שהוקלד על כל התאים המסומנים. Ctrl+D ממלא למטה, וגרירת ידית המילוי מעתיקה ערכים וממשיכה סדרות מספרים.
- העתקה והדבקה מאקסל וחזרה, ביטול וחזרה (Ctrl+Z / Ctrl+Y), סינון ערכים, מיון וחיפוש.
- בשורת המצב: ספירה, סכום וממוצע של התאים המסומנים.

### לשוניות פרויקט אוטומטיות
- כל ערך בעמודת הפרויקט, בהזמנות או ב-BOM, פותח לשונית.
- שם שמוחלף בטבלת ההזמנות מעדכן את הלשונית וגם את שורות ה-BOM של הפרויקט.
- שינוי שם בלשונית (לחיצה ימנית) מעדכן את שתי הטבלאות.

### תפקידים והרשאות עריכה
כל משתמש בוחר תפקיד בהרשמה. מנהל הרכש יכול לשנות תפקידים ב"משתמשים ותפקידים", ואת העמודות שכל תפקיד יכול לערוך ב"הרשאות עריכה לפי תפקיד".

| תפקיד | מה מותר לו כברירת מחדל |
|---|---|
| מנהל רכש | הכול: עריכה, ייבוא, מחיקה, ניהול עמודות, הרשאות ומשתמשים |
| קדם | עריכת כל העמודות (בעיקר סטטוס, עדכון ותאריכי אספקה), והוספת הזמנות |
| מנהל תפעול | עריכה של כמות נדרשת, כמות שהתקבלה ועדכון |
| קניין | הוספת הזמנות חדשות, עריכה מלאה של הזמנות שהוסיף, ועריכה של כמות נדרשת, כמות שהתקבלה ועדכון |

- בטבלה, עמודה שאסור לערוך מסומנת "קריאה בלבד" בכותרת.

### תזכורת יומית על הזמנות בעיכוב
- כל משתמש קובע ימים ושעות פעילות, בהרשמה או ב"הגדרות אישיות".
- פעם ביום, בתוך שעות הפעילות, מגיעה התראה למחשב עם מספר ההזמנות שבעיכוב לפי פרויקט. לחיצה עליה פותחת את הרשימה.
- כשהאפליקציה מותקנת ב-Chrome או ב-Edge, הבדיקה רצה גם ברקע. בכל דפדפן אחר היא רצה כשהאתר פתוח.

### התקנה כאפליקציה במחשב
- תפריט המשתמש ← "התקנה כאפליקציה במחשב", או סמל ההורדה בפס העליון.
- אחרי ההתקנה המערכת נפתחת בחלון משלה, עם סמל בשולחן העבודה.

### עוד
- **מצב כהה**: כפתור שמש/ירח בפס העליון.
- **מחוון טעינה**: בכל ייבוא מוצגים אחוזים, השלב הנוכחי ומספר השורות.
- **מחיקת טבלה**: כפתור "מחיקת הטבלה" (מנהל רכש), עם אישור בהקלדה וגיבוי לאקסל לפני המחיקה. בלשונית פרויקט נמחקות רק השורות של הפרויקט.
- **גיבוי וייצוא**: ייצוא לאקסל מכל טבלה, וגיבוי או שחזור של כל הנתונים כקובץ JSON.

## נפח נתונים

המערכת נבדקה עם 10,000 שורות ו-30 עמודות:

| פעולה | זמן |
|---|---|
| קריאת הקובץ | כ-0.8 שניות |
| ייבוא | כ-0.7 שניות |
| טעינה מחדש | פחות משנייה |
| עריכה של עמודה שלמה וביטול שלה | פחות מחצי שנייה |

השמירה המקומית משתמשת ב-IndexedDB של הדפדפן ולא ב-localStorage, שמוגבל ל-5MB. הנתונים נשמרים בגיטהאב כקובץ דחוס (gzip): 10,000 שורות תופסות כ-1MB במקום כ-10MB.

## איך הסנכרון עובד

כל שינוי נשמר מקומית מיד ונשלח לגיטהאב אחרי שנייה. כל 12 שניות, וגם כשחוזרים ללשונית הדפדפן, המערכת בודקת אם יש עדכונים ממשתמשים אחרים.
המיזוג נעשה ברמת השורה: אם שני משתמשים עורכים שורות שונות באותו זמן, נשמרים השינויים של שניהם. אם שניהם ערכו את אותה שורה, נשמרת העריכה האחרונה.
אם אין חיבור לאינטרנט, השינויים נשמרים במכשיר ונשלחים כשהחיבור חוזר.
